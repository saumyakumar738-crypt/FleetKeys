# Fleet Garage Key Tracking System — Employee Mobile App Prototype

## 1. Objective

Build a **high-fidelity, mobile-first employee application prototype** for a fleet garage where every vehicle key is digitally tracked using QR codes.

The primary objective is to **eliminate lost/unaccounted-for keys by ensuring that every key always has one clearly identified custodian**.

The application will be used dozens of times a day by **mechanics, supervisors, service advisors, and other garage employees**, so the workflow must be extremely fast, intuitive, and require minimal taps.

The design should feel like a modern enterprise application similar to **Uber Fleet, Microsoft enterprise apps, or other professional operations tools**.

### Design principles

* Mobile-first
* Optimized for one-handed use
* Very fast workflows
* Minimal number of taps
* Large touch-friendly buttons
* Clean white background
* Blue as the primary action color
* Rounded cards
* Minimal icons
* Clear typography
* Strong visual hierarchy
* Enterprise/professional appearance
* Clear success, error, warning, and pending states
* Every important action should provide immediate visual feedback
* Do not leave the user on a screen with no visible result after an action

The prototype should include **realistic navigation and interactive state changes between screens**, not just static wireframes.

---

# 2. Core Key Ownership Logic

Every vehicle key must always have one of these states:

1. Assigned to an employee
2. Transfer pending
3. Transfer completed
4. Transfer rejected
5. Transfer expired
6. Missing / not physically held by the custodian

### Important ownership rule

The **current custodian remains the owner until the receiver explicitly accepts the transfer**.

When a sender initiates a transfer:

* Sender selects the employee who should receive the key.
* Sender becomes the "Transfer Initiator".
* Receiver receives an incoming-transfer notification.
* Receiver must physically scan the vehicle's QR code.
* Receiver can then accept or reject the transfer.
* Ownership changes **only after the receiver accepts**.
* If receiver rejects, sender remains custodian.
* If receiver does not complete the process within 2 minutes, the transfer expires and sender remains custodian.
* The sender must always be able to see the current transfer status.

# 6. VERY IMPORTANT — Updated Transfer Flow

The transfer workflow has been intentionally changed.

### Sender initiates the transfer

The **sender does NOT scan the QR code to complete the transfer**.

Instead:

1. Sender opens **My Keys**
2. Sender selects the vehicle/key
3. Sender clicks **Send Key**
4. Sender selects the receiving employee
5. Sender clicks **Transfer Key**
6. The transfer becomes **Pending**
7. Receiver receives an **Incoming Key Transfer** notification
8. Receiver opens the notification
9. Receiver is automatically taken to the **QR Scanner**
10. Receiver scans the QR code on the physical vehicle key
11. The system identifies the pending transfer
12. Receiver is shown the transfer details
13. Receiver chooses **Accept** or **Reject**
14. Ownership changes only when receiver clicks **Accept**

This is critical: **the QR scan is performed by the receiver, not the sender.**

# 20. Bulk Send Keys

Add a **Bulk Send** option.

This should allow an employee who currently holds multiple keys to transfer multiple keys to the same employee in one workflow.

### Bulk Send Flow

1. Tap **Bulk Send**
2. Display all keys currently assigned to the employee
3. Allow multi-select using checkboxes/cards
4. Display selected count
5. Tap **Continue**
6. Select receiving employee
7. Display a transfer summary

Example:

**5 Keys Selected**
**Sending To: Amit Patel**

Show all selected vehicle numbers.

Then:

**Send Keys**

After confirmation:

* Create a bulk transfer request
* Show a clear **Waiting For Acceptance** state
* Show the 2-minute countdown
* Receiver receives a bulk incoming-transfer notification
* Receiver scans QR codes for the selected keys

### Bulk transfer acceptance

Design this so the receiver can process the bulk request efficiently.

The receiver should be able to see:

**5 Keys Pending**

and scan each vehicle/key QR code.

For each successfully scanned key, show:

**Verified ✓**

After verification, allow:

**Accept All**

or allow individual acceptance/rejection where necessary.

Ownership should change only for the keys that the receiver successfully accepts.

Make the bulk flow fast enough for operational use.

# 25. Missing Keys / Financial Impact Notifications

Create an automated notification/report that is sent **every 3 days** to the relevant stakeholders.

The report should provide a summary of missing/unaccounted-for keys and the estimated financial impact to the company.

### Missing Keys Report

**Reporting Period:** Last 3 Days
**Missing Keys:** 12
**Estimated Cost:** ₹24,000

* Cost per missing key, where applicable
* Vehicles affected
* Departments affected
* Employees/custodians associated with missing keys

* Number of previously missing keys
* Number of keys recovered

The notification should be sent to configurable stakeholders such as:

* Garage Manager
* Operations Manager
* Regional/City Operations
* Other designated stakeholders

### Cost calculation

The prototype should support a configurable **cost per key** or key replacement value.

Example configuration:

`KEY_REPLACEMENT_COST = ₹2,000`

Then:

**Total Missing Key Cost = Number of Missing Keys × Replacement Cost**

Do not hard-code the final business value. Make it configurable.
